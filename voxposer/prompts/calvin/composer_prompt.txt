# ============================================================================
# COMPOSER
# ============================================================================
# Turn ONE instruction for a robot arm at a play table into 1-2 stages.
#     (aff_fn, avoid_fn, mode, primitive, object)               # normal stage
#     (aff_fn, avoid_fn, rot_target, mode, primitive, object)   # stage that also turns the wrist
#   aff_fn      get_affordance_map('<where the gripper should go>')
#   avoid_fn    get_avoidance_map('<where it must not go>'), or None
#   mode        'track' when the target is an object's own centre (it follows the
#               object); 'static' for every offset target ("N cm left of X").
#   primitive   one of: grasp, push, pull, place, rotate
#   object      one of: red_block, blue_block, pink_block, block, drawer_handle,
#               slider_handle, led_button, lightbulb_switch
# Stages run in order; the next starts when the gripper reaches the current target.
# Directions are the robot's: left / right, in front of (toward the robot) /
# behind (away from it), above / below.
#
# ============================================================================
# THE SCENE: what is there and how each thing moves
# ============================================================================
#   blocks (red, blue, pink)   Graspable cubes. They are grasped and carried.
#   drawer                     Also called cabinet drawer, or a compartment. Slides
#                              front <-> back.
#                              Its handle is GRASPED and
#                              PULLED toward the front to open, and PUSHED toward
#                              the back to close. Things go into the
#                              'drawer interior'. It is the only thing here that
#                              is ever open or shut (closed, pulled out, pushed
#                              in): an instruction that speaks of something open
#                              or shut without naming it means the drawer.
#   sliding cabinet            Also called slider, sliding door, shelf, or just
#                              "the cabinet" (but "cabinet drawer" is the drawer).
#                              The door slides left <-> right when its
#                              'slider handle' is PUSHED. The cabinet is never
#                              called open or shut: the door covers one half and
#                              leaves the other uncovered. Things go into that
#                              half, written
#                              'the uncovered side of the slider interior'.
#   light switch               A lever for the yellow light (lightbulb, yellow
#                              lamp). PUSHED up = on, PUSHED down = off, always
#                              with two push stages, never a single press. A
#                              short lever: drive only 7cm past it.
#                              Object: lightbulb_switch.
#   button                     PRESSED to toggle the green light (LED, indicator
#                              light, lamp); the same press turns it on and off.
#                              Object: led_button.
# WHICH BLOCK. A colour in the instruction settles it. Every other block is
# settled by RESOLVE FIRST (below), which asks the scene. A held block that is
# being put somewhere needs no name: only its destination is named, and its
# object is 'block'. An affordance query names a block by its colour and
# nothing else.
#
# Plan only the motion the instruction asks for. Never add stages that first
# open or close something.
#
# ============================================================================
# THE FIVE MOTION PATTERNS: every plan is exactly one of these
# ============================================================================
# CARRY         A block ends up somewhere else (lift, pick up, move, push, slide,
#               put, stack, take off). Stage 1: grasp at its centre (track).
#               Stage 2 (static): the destination.
#                 lift / pick up / take off .... 15cm above it       (grasp)
#                 move / push / slide sideways . 15cm in that direction (place)
#                   (a block is only ever moved LEFT or RIGHT, so a direction
#                   given by a landmark is settled as left or right)
#                 onto another block ........... 5cm above that block (place)
#                 put / place / store into the
#                 drawer or the cabinet ........ its interior         (place)
#               A block that is in the drawer, or in / on the sliding cabinet
#               (the shelf), is lifted with stage 1 alone.
#               A block is never moved with push stages, except when the
#               instruction says to push / slide / sweep / knock it INTO the
#               drawer, however the drawer is named (see PUSH-THROUGH).
# PULL          Opening the drawer. Stage 1: grasp the handle's centre (track).
#               Stage 2: pull to a point 15cm along the motion (static).
# PUSH-THROUGH  A door, a drawer being closed, the lever, or a block pushed / slid /
#               swept into the drawer. Two push stages, both static, no grasp stage even if
#               the instruction mentions grasping:
#               Stage 1: a point 5cm from the object on the side OPPOSITE the motion.
#               Stage 2: a point 12cm past the object ALONG the motion.
# PRESS         The button. One push stage at the button (track).
# TURN          Rotating a block. Stage 1: grasp at its centre (track). Stage 2:
#               rotate at the SAME centre (track) with
#               rot_target = rotation_about_axis('z', ANGLE)
#               ANGLE = +90 for left (counter-clockwise from above), -90 for right.
#               The target is the turn itself, relative to the wrist's pose now.
#
# The `# Held block: X` line that opens each query is reliable gripper state. It
# matters in ONE case: the instruction asks to put the held thing somewhere (put /
# place / store / stack "the object", "it", "the grasped block"). Then skip the
# grasp stage of CARRY and emit only the place stage, with object 'block'. For
# every other instruction, plan exactly as if nothing were held, with all of
# the pattern's stages.
#
# ============================================================================
# RESOLVE FIRST: what the instruction leaves to the scene
# ============================================================================
# Settle ONCE, at the top of the plan, whatever the instruction leaves to the
# scene, by asking where things are. Then write the plan exactly as if the
# instruction had named the colour, the light, and left or right.
#   a block without a colour: ask which block the instruction means. `instruction`
#   holds the instruction's text; never retype or shorten it.
#       name = parse_query_obj(f'the block meant in: {instruction}').name.replace('_', ' ')
#       obj = name.replace(' ', '_')          # name is e.g. 'red block', obj 'red_block'
#     When one block goes onto another, ask for each:
#       name = parse_query_obj(f'the block to pick up in: {instruction}').name.replace('_', ' ')
#       base = parse_query_obj(f'the block to stack onto in: {instruction}').name.replace('_', ' ')
#   a sideways direction given by a landmark
#       side = toward(name, '<landmark>')     # "toward the <landmark>": 'left' or 'right'
#       side = away_from(name, '<landmark>')  # "away from the <landmark>"
#       side = toward(name, 'table')          # "inward": toward the middle of the table
#     Always get the side from toward() / away_from(), never by guessing. The
#     affordance queries then say "to the {side} of": never "toward", "away" or
#     "inward". The side only replaces left / right: the motion pattern stays
#     that of the object (a block is CARRIED, the door is pushed through).
#   a light described only by where it is ("the light on the left")
#       light = parse_query_obj('<description of the light>').name    # 'lightbulb' or 'led'
#     then PUSH-THROUGH on the light switch for the lightbulb, PRESS for the led.
#     A light the instruction does not identify at all ("it", "the light") is
#     the yellow light: plan exactly as for "the yellow light".
# The `# Held block` line outranks the instruction: if the instruction speaks of
# a held block but the line says none, nothing is held, so resolve the block and
# plan all the stages.
#
# A `# Scene state` block may follow the held-block line. It is a camera's guess
# at the scene. Use its ambiguous_resolutions only for a word that names nothing
# by itself ("it", "that one"). Never use it to choose a block or to override what
# the instruction or RESOLVE FIRST already settles.
# ============================================================================
